================================================================================
FLOODWATCH API ARCHITECTURE - QUICK REFERENCE
================================================================================

FRAMEWORK: Django REST Framework 3.15.2
DOCS TOOL: drf-spectacular 0.28.0 (OpenAPI 3.0)
GEO SUPPORT: djangorestframework-gis 1.1
RASTER: TiTiler 0.18.4 (COG serving)
WMS/WMTS: MapServer
AUTH: JWT, Token, Session, OAuth2

================================================================================
AUTHENTICATION CONFIGURATION
================================================================================

JWT SETTINGS (in base.py):
  - Access token lifetime: 1 hour
  - Refresh token lifetime: 7 days
  - Token rotation: enabled
  - Blacklist after rotation: enabled
  
Default Permission: AllowAny (globally configured)
Per-endpoint overrides: @permission_classes()

Methods:
  1. JWT (primary)
  2. Token Auth (Django built-in)
  3. Session Auth (fallback)
  4. Google OAuth (custom implementation)

================================================================================
WHAT'S IMPLEMENTED vs. NOT
================================================================================

IMPLEMENTED:
  ✅ RESTful GeoJSON APIs with pagination
  ✅ TiTiler COG serving & dynamic tiles
  ✅ WMS/WMTS via MapServer
  ✅ Multiple authentication methods
  ✅ OpenAPI documentation (Swagger/ReDoc)
  ✅ Date-based temporal queries
  ✅ Report workflow endpoints
  ✅ GCS signed URL generation (GeoSFM)
  ✅ Raster statistics via TiTiler

NOT IMPLEMENTED:
  ❌ STAC API (no /collections/, /search/)
  ❌ pgSTAC integration
  ❌ Vector tiles (MVT)
  ❌ WFS via DRF (MapServer only)
  ❌ Tipg/PostGIS advanced queries
  ❌ API versioning (v1, v2, etc.)
  ❌ Rate limiting
  ❌ Response caching layer
  ❌ GraphQL API
  ❌ Advanced spatial filters

================================================================================
RESPONSE FORMATS
================================================================================

All endpoints return JSON.
Vector data endpoints return GeoJSON FeatureCollections.

Example vector response:
  {
    "type": "FeatureCollection",
    "features": [
      {
        "type": "Feature",
        "geometry": {...},
        "properties": {...}
      }
    ]
  }

Pagination (default):
  Page size: 100 items
  Query params: ?page=1, ?page_size=50
